# 琉璃观测台 · 项目需求说明（交接给开发 AI）

> 这是项目最初交给开发 AI 的需求文档，原样保留作为设计依据。实际实现和它的差异见仓库根目录的 README。

> 这份文档写给接手开发的 AI 编程助手。读完就能开工；不清楚的地方先问站长，不要猜。
> **全程用简体中文和站长交流。**

---

## 1. 一句话

做一个**基于服务器访问日志**的网站监控报表服务，效果和体验对标宝塔面板的「网站监控报表」（见 `参考/宝塔网站监控报表-概览.png`），但不依赖宝塔，部署在 1Panel 上，界面是琉璃风格。

## 2. 背景与站长的明确偏好

- 站长不喜欢宝塔，但很喜欢宝塔的「网站监控报表」：直观、数据全、不用在网页里加 JS。
- **已试过并否决的方案**：Cloudflare 自带统计（太慢）、往网页里加 JS 的统计（例如 Microsoft Clarity 一类，数据不如宝塔直观，也统计不到蜘蛛、状态码、流量）。**不要再推荐这类方案。**
- 宝塔的报表本质是**分析 Nginx 访问日志**，本项目也一样：数据来源只用 OpenResty/Nginx 访问日志，**不往网站页面里注入任何 JS**。
- 站长要的是「一劳永逸」：架构要**支持多台服务器汇总**，但未来很长时间只有一台服务器。所以**按多台设计数据模型和接口，第一版只实现并交付单台模式**。如果多台的设计会让第一版明显变复杂，就退回只设计单台，并在文档里写清以后怎么扩展。
- **封禁 IP 第一版不做，但必须做**：第一版要把接口、数据结构、界面位置预留好，第二版补上。
- 动效不要跟随系统「减少动态效果」设置做降级（站长自己的电脑关了动画效果，做降级会导致他看到的是静止或卡住的界面）。

## 3. 运行环境（站长的服务器）

| 项 | 情况 |
|---|---|
| 服务器 | 香港 VPS，一台。直连 Docker Hub / npm / Go 官方源，不需要国内镜像 |
| 面板 | 1Panel；网站由 1Panel 应用商店的 **OpenResty** 承载，反向代理到各站点容器 |
| 已有网站 | `sosoquark.com`（琉璃搜索，Astro + MySQL，容器名 `liuli`）。以后还会加网站 |
| 部署方式 | docker-compose，由 1Panel「容器 → 编排」管理。compose 里自建镜像要写 `pull_policy: build`，否则 1Panel 会去仓库拉取而失败（踩过的坑） |
| 网络 | 1Panel 自带外部网络 `1panel-network` |
| 访问 | 观测台自身只监听 `127.0.0.1`，由 OpenResty 反代并配 HTTPS（例如 `stats.sosoquark.com`） |
| 可能套 Cloudflare | 是。真实访客 IP 要支持从 `CF-Connecting-IP` / `X-Real-IP` 取 |

**日志位置需要到服务器上确认**：1Panel 的 OpenResty 网站日志一般在
`/opt/1panel/apps/openresty/openresty/www/sites/<域名>/log/access.log`（不同 1Panel 版本可能不同）。
开工第一步就请站长在服务器上 `ls` 一下实际路径并贴给你，不要凭记忆写死。

## 4. 架构

```
┌─────────────── 每台服务器 ───────────────┐
│ OpenResty 访问日志（JSON 格式，每个站点一个文件）│
│        │ 只读挂载，tail，处理日志切割           │
│        ▼                                       │
│   Agent：解析 → 按分钟聚合 + 保留明细           │
└────────┼────────────────────────────────────┘
         │ 单台模式：进程内直接写；多台模式：HTTPS + Token 推送
         ▼
   Hub：存储（SQLite WAL）+ 查询 API + 网页仪表盘（登录后访问）
```

- **同一个程序、三种模式**：`all-in-one`（默认，单台：Agent + Hub 同进程）、`agent`、`hub`。第一版交付 `all-in-one`。
- **所有数据表从第一天起就带 `server_id` 和 `site` 字段**，以后加机器不需要迁移数据。
- Agent → Hub 的推送接口（第一版可以只定义不实现）：批量上报分钟聚合 + 明细样本，按 `(server_id, site, minute)` 幂等，带 Token 鉴权。
- 断点续读：记住每个日志文件的 inode + 偏移量，重启不重复、不丢失；能正确跟上 logrotate 切割。

### 技术栈建议

推荐 **Go 单二进制**（内存占用低，静态编译，镜像小），SQLite 用纯 Go 驱动（例如 `modernc.org/sqlite`），前端打包后嵌入二进制，图表用 ECharts。如果你有更好的理由选别的技术栈，先和站长说明再定。

### 日志格式

在 OpenResty 里定义一个 JSON 日志格式，各站点的 `access_log` 用它。请给站长写清楚**在 1Panel 里改哪里**（OpenResty 设置 → 配置修改 → `http` 块；站点的 `access_log` 指令）。建议字段：

```nginx
log_format liuli_json escape=json '{'
  '"t":"$time_iso8601","host":"$host","ip":"$remote_addr",'
  '"xff":"$http_x_forwarded_for","cfip":"$http_cf_connecting_ip",'
  '"m":"$request_method","uri":"$request_uri","st":$status,'
  '"bytes":$bytes_sent,"rt":$request_time,"urt":"$upstream_response_time",'
  '"ref":"$http_referer","ua":"$http_user_agent","proto":"$server_protocol"'
'}';
```

同时兼容 Nginx 默认的 combined 格式作为后备（字段会少：没有耗时）。

## 5. 指标口径（务必统一，并在界面的问号提示里写清）

| 指标 | 口径 |
|---|---|
| 请求 | 所有日志行 |
| 浏览量 PV | 非蜘蛛、状态码 2xx/3xx、**页面类请求**（排除 js/css/图片/字体/视频等静态资源和 `/api/` 等接口路径，排除规则可配置） |
| 访客 UV | 当天去重的（IP + UA）哈希，非蜘蛛 |
| IP 数 | 当天去重 IP |
| 流量 | `bytes_sent` 之和（出站） |
| 蜘蛛爬虫 | UA 命中已知蜘蛛列表的请求数；按搜索引擎分组 |
| 10 分钟活跃用户 | 最近 10 分钟去重访客数 |
| 对比 | 「前一天」「上周同期」叠加在趋势图上（同截图） |

**假蜘蛛识别**（宝塔没有，加分项，可放第二版）：对自称百度/谷歌/必应蜘蛛的 IP 做反向 DNS + 正向校验，结果缓存，标记假冒。

## 6. 功能范围

### 第一版（必须）

对照宝塔左侧菜单：

1. **概览**（截图那一页）：网站下拉选择、时间（今日/昨日/近 7 天/近 30 天/自定义）、10 分钟活跃用户 + 小柱状图、PV/UV/IP/请求/流量/蜘蛛 六个指标卡（下方小字是对比值）、趋势图（指标可切换，颗粒度分钟/小时，可叠加前一天/上周同期）、性能（QPS、平均响应耗时）、实时流量
2. **网站列表**：每个站点今日核心指标一览，点进去看概览
3. **IP / 地区**：Top IP（次数、流量、地区、最近访问）、地区分布（国内到省，用离线 IP 库 ip2region；国外到国家）
4. **访客 / 客户端**：浏览器、操作系统、设备类型分布
5. **蜘蛛**：各搜索引擎的抓取次数、趋势、抓取最多的 URL
6. **URI / 来源**：Top 页面、Top 来源（Referer 域名）、搜索引擎来源
7. **状态码**：分布 + 趋势，点击可看对应明细
8. **错误日志**：4xx/5xx 请求明细（时间、IP、URI、状态、UA），可筛选
9. **慢请求**：按 `request_time` 排序的明细，阈值可配
10. **登录**：单管理员账号，密码 bcrypt，会话 Cookie（HttpOnly、Secure、SameSite），登录失败限流
11. **设置**：日志路径与站点的对应关系、PV 排除规则、数据保留天数、慢请求阈值

### 第二版（必须做，第一版预留好位置）

- **封禁 IP**：在 IP 列表、错误日志、实时访问里一键封禁/解封，支持到期自动解封。实现思路：生成一个 deny 规则文件给 OpenResty `include`，然后让 OpenResty 重载。重载方式（1Panel API / docker exec / 信号）要和站长商量，涉及给容器什么权限，**先讲清楚风险再做**
- **告警**：5xx 突增、流量暴涨、疑似 CC（单 IP 短时请求过多）时推送到 Telegram 或企业微信
- **自动封禁**：命中 CC 阈值自动封，可配置白名单
- **大屏**：全屏实时大屏（琉璃风格，可用下面提到的琉璃动画组件做背景）
- **多台模式**：`agent` / `hub` 模式实际可用

## 7. 数据存储建议

- 明细表：保留 7 天（可配），用于明细查询和「今日」统计。站长当前量级约每天 10 万请求，SQLite 完全够用
- 小时 / 天聚合表：保留 1 年，用于近 30 天和更长时间的查询
- UV/IP 跨时段去重：天级用去重集合或 HyperLogLog，按你的判断选，但口径要和上面一致
- 定时清理过期数据，数据库体积可控

## 8. 界面风格

- 中文界面，琉璃风格，**不要做成通用的 AI 管理后台模板**
- 设计参考：
  - 琉璃搜索（sosoquark.com）的 `DESIGN.md`：设计系统（乳白台面底色、墨色文字、油性笔红做强调、琥珀色、毛玻璃组件）
  - 字体：**阿里巴巴普惠体 3.0**，琉璃搜索项目里已切好分片（`public/fonts/puhuiti/` + `src/styles/fonts.css`），可直接复用
  - 「前端琉璃」：琉璃液态玻璃 WebGL 动画组件（站长很喜欢），可用在登录页或大屏，**不要用在需要专注看数据的页面上**
- 布局可以参考宝塔（左侧菜单 + 右侧内容），但视觉要是琉璃的；手机上也要能看概览
- 图表配色统一，状态码用固定色（2xx 绿、3xx 蓝、4xx 琥珀、5xx 红）

## 9. 安全要求

- 观测台只监听 `127.0.0.1`，经 OpenResty HTTPS 访问
- 必须登录；接口全部鉴权；登录限流；不做注册
- 日志目录**只读挂载**
- 给网页加安全响应头（CSP、X-Frame-Options 等）
- 多台模式的推送接口用 Token，Token 只存服务端
- 不收集、不展示超出访问日志范围的个人信息；IP 等数据只留在站长自己的服务器上

## 10. 交付物

- 项目代码用 git 管理，提交信息写中文
- `Dockerfile`、`docker-compose.yml`（含 `pull_policy: build`、只读挂载日志、加入 `1panel-network`、端口只绑 127.0.0.1）
- `部署说明.md`：照着 1Panel 一步步点就能完成（包括改 OpenResty 日志格式、建编排、配反代和 HTTPS、首次登录）
- 一个**日志生成器 / 示例日志**，在本地没有真实日志时也能跑起来演示和测试
- 本地测试通过后，用截图在手机宽度和电脑宽度下自查一遍

## 11. 验收标准（第一版）

1. 在 1Panel 上按部署说明能装起来，登录后能看到 `sosoquark.com` 的数据
2. 概览页的六个指标、趋势图（含前一天对比）、10 分钟活跃用户能正确显示，数字和日志手工统计结果一致（在部署说明里给出核对方法）
3. IP/地区、客户端、蜘蛛、URI/来源、状态码、错误日志、慢请求页面都可用
4. 重启容器、日志切割后数据不丢不重
5. 新增一个网站时，只要在设置里加一条「站点 ↔ 日志路径」就能统计
6. 资源占用：日常内存 < 100MB
7. 界面是琉璃风格，手机能看概览

## 12. 工作方式

- 开工前先给站长一个简短的实施计划（模块划分、技术栈、第一版里程碑），确认后再写代码
- 需要站长提供的东西（日志实际路径、1Panel 版本、要用的二级域名）一次性列出来问
- 涉及服务器操作的步骤写进文档让站长自己执行，你没有服务器权限
- 站长不是专业运维，但也不是小白：说明要具体到「在 1Panel 哪个菜单点哪里」，不需要解释基础概念
